# 开发过程记录

## 项目目标

完成川山甲战队视觉组正式队员考核方向一：基于 ROS 2、OpenCV 与
AprilTag 的单目三维视觉和增强现实系统。

## 环境与系统架构

- 操作系统：Ubuntu 22.04。
- 机器人中间件：ROS 2 Humble。
- 编程语言与主要库：Python 3.10、OpenCV、NumPy、rclpy、cv_bridge、tf2_ros。
- ROS 2 包：`apriltag_ar`，使用 `ament_python` 构建。
- 摄像头：USB 摄像头 `/dev/video0`，采用 V4L2 + MJPG。
- 标签：AprilTag 36h11，检测 ID 为 0，外围正方形边长为 `0.0575 m`。

系统包含标准 ROS 图像话题路线和摄像头直连路线。标准路线由
`camera_publisher` 发布 `/camera/image_raw`，再由检测节点订阅；直连路线由
`apriltag_direct` 在同一进程读取摄像头并复用检测处理逻辑。

## 相机链路与低延迟处理

- 图像尺寸设置为 640×480，目标帧率为 30 FPS，摄像头缓冲区深度为 1。
- 标准图像路线使用传感器数据 QoS、`BEST_EFFORT` 和较小队列，减少旧帧堆积。
- 直连路线绕过 ROS 图像传输、CvBridge 转换和显示链路中的额外排队，内部处理速度约为
  26–27 FPS。
- 手动曝光和 50 Hz 防闪烁设置用于减轻手机屏幕显示标签时的亮度变化。

## 相机标定与标签几何

相机标定结果接入检测节点，内参为：

- `fx = 675.85100`，`fy = 683.09268`；
- `cx = 325.73900`，`cy = 214.65946`；
- 畸变系数为 `[0.181898, -0.521402, 0.005301, 0.005508, 0]`；
- 畸变模型为 `plumb_bob`。

运行分辨率与标定分辨率保持一致。标签尺寸采用外围正方形的实测边长
`0.0575 m`，不采用内部编码单元的尺寸。

## AprilTag 检测与位姿估计

检测节点完成以下图像处理和 ROS 输出：

1. 使用 OpenCV ArUco 的 `DICT_APRILTAG_36h11` 字典检测标签；
2. 绘制标签 ID、P0–P3 四角点、中心点和三维坐标轴；
3. 使用 `SOLVEPNP_IPPE_SQUARE` 根据标签角点、实际边长和相机参数估计位姿；
4. 发布 `/apriltag/pose`、`/tf` 和 `/apriltag/markers`；
5. 建立 `camera_frame` 到 `apriltag_0` 的坐标变换；
6. 对平移量使用指数滤波，平衡跟手性和画面稳定性。

## RViz2 与 AR 拓展

RViz2 中设置 `Fixed Frame` 为 `camera_frame`，显示相机模型、标签平面、TF 坐标系、
MarkerArray 和连接线。AR 拓展把 AprilTag 坐标系作为参考，在标签前方设置固定三维偏移，
构造虚拟立方体的八个顶点并投影到图像平面。相机移动或旋转时，立方体随标签保持相对静止，
并呈现对应的透视变化。

## 稳定性问题与处理

- 图像话题链路存在排队和延迟时，使用低缓冲和摄像头直连路线改善跟手性。
- 手机屏幕亮度变化明显时，使用手动曝光和防闪烁设置减轻画面闪烁。
- 标签外围保留白色静区时，正面识别更稳定；纯黑背景会降低正面识别成功率。
- 近距离约 10 cm 时摄像头无法稳定对焦，标签不能持续识别，作为失败案例保留。

## 数据流与验证结果

1. USB 摄像头通过 V4L2/MJPG 采集 640×480 图像；
2. OpenCV 检测 AprilTag 36h11 并提取四角点；
3. 结合相机标定参数和标签实测边长估计三维位姿；
4. 发布 Pose、TF、MarkerArray 和处理后图像；
5. 通过 OpenCV 窗口验证标签标注与 AR 效果，通过 RViz2 验证三维坐标关系；
6. 通过不同距离的实测数据分析测距误差和近距离失焦边界。
